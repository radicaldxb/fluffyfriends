# Locked workflow – fallback documentation

This document locks in the **known-good n8n workflow** for FluffyFriends so you always have a fallback.

---

## Locked workflow file

**File:** [`docs/n8n-fluffyfriends-working.json`](./n8n-fluffyfriends-working.json)

- **Purpose:** Canonical export of the transform-pet workflow. Webhook → HTTP Request → Extract from File → Merge (with style branch) → GEMINI → Convert to File → Supabase (POST to `/api/receive-n8n-image`).
- **Webhook path:** `transform-pet`
- **Webhook response:** `onReceived` (respond immediately so the app doesn’t time out).
- **Status:** Verified working (production webhook, full flow through n8n).

**Do not edit this file by hand.** To update the locked workflow:

1. In n8n, get the workflow running correctly (production URL, executions succeeding).
2. Export it from n8n (workflow menu → Download).
3. Replace `docs/n8n-fluffyfriends-working.json` with the new export.
4. Update this section with the date and any one-line note (e.g. “Added node X”).

---

## How to restore from fallback

If the workflow in n8n is broken or lost:

1. In n8n: **Workflows** → **Import from File**.
2. Choose **`docs/n8n-fluffyfriends-working.json`** from this repo.
3. Reconnect credentials (Google Drive if used, Gemini API key in the HTTP Request node, etc.).
4. Set the **Webhook** node to **Respond: On Received** (not “When last node finishes”).
5. **Activate** the workflow.
6. In Netlify, set **N8N_WEBHOOK_URL** to the workflow’s **Production** URL (e.g. `.../webhook/transform-pet`), then redeploy.

---

## What this workflow expects

- **App:** POST to `N8N_WEBHOOK_URL` with JSON `{ test_image, pet_name, name }`. The app uses `N8N_WEBHOOK_URL` for `/create` and the full flow.
- **n8n:** Fetches image from `test_image`, runs style branch (Edit Fields → Download file → Master_Fireman) and pet branch (HTTP Request → Extract from File), merges, calls GEMINI, then POSTs to `https://fluffyfriends-dev.netlify.app/api/receive-n8n-image` with `image_base64`, `pet_name`, `original_image_url` (use `test_image`), `status`.
- **Supabase:** Table `pet_portraits` with `original_image_url` column; storage bucket `images` with `generated/` (and `uploads/` for app uploads). See `supabase/run-*.sql` and `docs/CREATE_PORTRAIT_FLOW.md`.
